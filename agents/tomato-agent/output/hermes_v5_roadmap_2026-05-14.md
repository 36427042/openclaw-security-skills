# 🪖 Hermes V5 路线图草案

> 起草时间: 2026-05-14 12:50
> 当前版本: Hermes V3.3 + DeerFlow + EvoMap

## 现状分析

### V3.3 工作流
```
天赐指令 → 土豆判断 → hermes_engine.py run --subtasks → 伙伴脚本执行 → 产出
```
- ✅ 单伙伴/多伙伴派遣稳定
- ✅ 全链路 workflow deerflow 可用
- ✅ 6伙伴 SOUL.md 全量框架绑定
- ✅ EvoMap 心跳保活
- ⚠️ 伙伴脚本通过 subprocess 调用，无法获取实时进度
- ⚠️ 错误处理依赖 EvoMap failures.jsonl，不够即时
- ⚠️ 任务状态无持久化（重启丢失）

### 当前瓶颈
1. **无实时反馈** — 派遣后只能等结果，中间无进度条
2. **无任务队列** — 多个任务时手动串行/并行
3. **无智能路由** — 所有任务走同一引擎，无负载均衡
4. **错误恢复弱** — 伙伴失败后依赖cron重试

## V5 愿景

### 核心改进
```
天赐指令 → 土豆判断 → Hermes V5 队列 → 智能路由 → 并行执行 → 实时回调 → 飞书汇报
                         ↓
                    EvoMap 状态同步
                         ↓
                    7虾面板可视化
```

### Phase 1: 任务队列 + 持久化（优先级最高）
- [ ] `task_queue.json` — 持久化任务状态
- [ ] 任务优先级：紧急(天赐直发) > 高(选品/发布) > 中(文案/审核) > 低(优化/文档)
- [ ] 任务重试：失败任务自动重试3次，超3次→搁置→汇报
- [ ] 并发控制：最多3伙伴并行（防止CPU过载）

### Phase 2: 实时WebSocket回调
- [ ] 伙伴脚本执行通过 ws 推送进度
- [ ] 土豆收到实时状态 → 决策是否干预
- [ ] 错误立即通知（非cron等待）
- [ ] 集成到7虾面板实时显示

### Phase 3: 智能路由
- [ ] 伙伴负载检测（CPU/内存/当前任务数）
- [ ] 自动选择最空闲伙伴
- [ ] 任务拆分（大任务自动拆子任务分发）
- [ ] 结果聚合（多伙伴产出合并）

### Phase 4: 全自动化闭环
- [ ] 豌豆触发选品 → 生菜自动接文案 → 苦瓜自动审 → 玉米自动做视频 → auto_publish
- [ ] 全链路无人值守
- [ ] 天赐仅需审批"是否上架"（一键确认）
- [ ] 日报自动生成+推送

## 技术选型

| 组件 | 候选 | 理由 |
|:-----|:-----|:-----|
| 任务队列 | Redis RQ / Python Queue | RQ重量级但可靠，Queue轻量但重启丢 |
| 持久化 | SQLite / JSON | SQLite支持并发，JSON更简单 |
| WebSocket | FastAPI ws / ws库 | FastAPI与DeerFlow技术栈一致 |
| 状态同步 | EvoMap A2A | 已有基础设施 |

## 建议优先推进

1. **Phase 1 任务队列** — ROI最高，1-2天可完成
2. **Phase 2 实时回调** — 提升用户体验
3. Phase 3-4 根据Phase 1-2反馈调整
