> **作者**：🫘豌豆
> **目的**：基于EchoTik现有数据构建「选品成功率预测模型」，用历史数据回测验证

## 一、模型概述

### 为什么需要选品验证模型
选品不是拍脑袋——每个品类、每款产品的表现是由多个可量化因子共同决定的。我们需要一个模型，在**上架前**就能给出相对科学的成功率预测，而非等7天数据出来后才知道好坏。

### 模型定位
```
输入：EchoTik品类/产品标签数据  ──┐
                                  ├──→ 成功率预测 + 预计7天出单量
输入：历史上架产品表现数据  ──────┘
                                  ↓
                         反哺选品决策：
                         - 哪些品类值得优先?
                         - 哪些品类需要回避?
                         - 什么样的产品特征组合胜率最高?
```

### 核心假设
1. 市场热度（GPM趋势/涨幅）越高 → 消费者付费意愿越强 → 越容易出单
2. 竞争度（同类产品数/均价）越低 → 供给稀缺 → 越容易出单
3. 上架数量（同款价格带覆盖）越多 → 测试覆盖面越广 → 出单概率越高
4. 视频制造难度（能否拍出展示效果的视频）越低 → 转化效率越高

## 二、模型公式

### 成功率预测模型

```
P(success) = α₁ · Score(市场热度) + α₂ · Score(竞争生态) 
           + α₃ · Score(品类基础分) + α₄ · Score(利润空间)
           + α₅ · Score(内容适配度)

其中 α₁ + α₂ + α₃ + α₄ + α₅ = 1.0
初始权重：α₁=0.25, α₂=0.20, α₃=0.15, α₄=0.20, α₅=0.20
```

### 五维度评分细则

#### 维度1：市场热度 Score(市场) — 25%权重

| 子因子 | 数据源 | 计分规则 | 区间分 |
|:-------|:-------|:---------|:------:|
| GPM值 | EchoTik品类页 | ≥$120 → 100分, $80-120 → 80分, $50-80 → 60分, <$50 → 30分 | 0-100 |
| 7日GPM涨幅 | EchoTik趋势 | +20%以上→100, +10~20%→85, 0~10%→70, -10~0%→50, -20%以下→30 | 0-100 |
| 搜索热度趋势 | EchoTik搜索栏 | 上升→85, 平稳→60, 下降→30 | 30-85 |
| 季节因子 | 品类历史 | 旺季→100, 过渡季→70, 淡季→40 | 40-100 |

```
Score(市场热度) = 0.35×GPM分 + 0.30×涨幅分 + 0.20×搜索热度 + 0.15×季节因子
```

#### 维度2：竞争生态 Score(竞争) — 20%权重

| 子因子 | 数据源 | 计分规则 | 区间分 |
|:-------|:-------|:---------|:------:|
| 同类产品密度 | EchoTik品类 | <50个→100, 50-200个→75, 200-500个→50, >500个→30 | 0-100 |
| 竞品均价区间 | EchoTik商品页 | 目标价低于均价50%→低竞争100, 低于30%→80, 低于10%→60, 高于均价→30 | 0-100 |
| TOP10垄断度 | EchoTik榜单 | TOP10占GMV<30%→100, 30-50%→70, 50-70%→50, >70%→30 | 0-100 |
| 评论门槛 | 同类平均评论 | <200条→低门槛100, 200-500→75, 500-1000→50, >1000→30 | 0-100 |

```
Score(竞争) = 0.25×密度分 + 0.30×价格带分 + 0.25×垄断度分 + 0.20×评论门槛分
```

#### 维度3：品类基础分 — 15%权重

| 子因子 | 数据源 | 计分规则 | 区间分 |
|:-------|:-------|:---------|:------:|
| 历史出单率 | 🫘内部数据 | TOP30%品类→100, 中40%→70, 后30%→40 | 40-100 |
| 退款率 | 内部监控 | <3%→100, 3-5%→80, 5-10%→60, >10%→40 | 40-100 |
| 客单价舒适区 | 市场+定价 | $10-15(最佳区间)→100, $5-10→80, $15-25→70, >$25→50 | 50-100 |
| 上新更换频率 | 历史数据 | 7天出单率>50%→100, 30-50%→70, <30%→40 | 40-100 |

```
Score(品类基础) = 0.30×出单率分 + 0.25×退款率分 + 0.25×客单价分 + 0.20×上新效率分
```

#### 维度4：利润空间 — 20%权重

| 子因子 | 数据源 | 计分规则 | 区间分 |
|:-------|:-------|:---------|:------:|
| 毛利率 | 1688拿货价→定价 | >60%→100, 45-60%→80, 30-45%→60, <30%→30 | 0-100 |
| 绝对利润($) | (定价-总成本)×汇率 | >$8→100, $5-8→80, $3-5→60, <$3→30 | 0-100 |
| 广告ROI可行性 | 利润÷CPM推算 | ROAS>5→100, 3-5→80, 2-3→60, <2→30 | 0-100 |
| 单品备货成本 | 拿货价×首批数 | <$200→100, $200-500→80, $500-1000→60, >$1000→40 | 40-100 |

```
Score(利润空间) = 0.30×毛利率分 + 0.30×绝对利润分 + 0.25×ROI可行性分 + 0.15×备货成本分
```

#### 维度5：内容适配度 — 20%权重

| 子因子 | 数据源 | 计分规则 | 区间分 |
|:-------|:-------|:---------|:------:|
| 视频效果展示难度 | 玉米评估 | 直观效果好→100, 中等→70, 难展示→40 | 40-100 |
| 同品类视频爆款率 | EchoTik视频 | 出百万播放视频率>10%→100, 5-10%→80, 1-5%→60, <1%→40 | 40-100 |
| 达人合作意愿 | 品类匹配度 | 高→100, 中→70, 低→40 | 40-100 |
| 直播展示效果 | 品类特性 | 直播展示惊艳→100, 一般→70, 难展示→40 | 40-100 |

```
Score(内容适配度) = 0.35×效果展示分 + 0.25×爆款率分 + 0.20×达人意愿分 + 0.20×直播效果分
```

### 最终预测分级

| P(success)范围 | 预测等级 | 行动建议 | 预计7天出单量(参考) |
|:-------------:|:--------:|:---------|:------------------:|
| ≥85分 | 🟢 高概率成功 | 优先选品→批量上架→重点推广 | 10-20单 |
| 70-84分 | 🟢 较大概率 | 正常上架→7天观察→决策 | 5-10单 |
| 55-69分 | 🟡 中等概率 | 小规模测试→3天快速验证 | 2-5单 |
| 40-54分 | 🟡 低概率 | 仅作补品/平替→注意止损 | 1-2单 |
| <40分 | 🔴 极小概率 | 跳过当前，换选其他 | <1单(大概率挂蛋) |

## 三、预计7天出单量预测模型

### 公式
```
7天出单量 = exp(β₀ + β₁·P(success) + β₂·上架SKU数 + β₃·投放强度 + ε)

简化版（日常使用）：
7天出单量 ≈ P(success) * 上架SKU数 * 0.12 * 投放系数
```

### 各参数说明
| 参数 | 示例值 | 说明 |
|:----|:------:|:-----|
| P(success) | 0-100分 | 成功率预测 |
| 上架SKU数 | 5-20个 | 该产品上架变体数 |
| 投放系数 | 0.5-2.0 | 不投=0.5, 普通投=1.0, 重点投=1.5, 大推=2.0 |
| 基准常量β₀ | ~0.5 | 模型校准参数 |

### 示例计算
```
场景：美妆蛋，P(success)=78分，上架10个SKU，普通投放(系数=1.0)
7天出单量 = 78 × 10 × 0.12 × 1.0 = 93.6 ≈ 93单
                                        🟢 优于同行均值

场景：睫毛夹，P(success)=52分，上架5个SKU，不投(系数=0.5)
7天出单量 = 52 × 5 × 0.12 × 0.5 = 15.6 ≈ 16单
                                        🟡 需观察，可能低于预期
```

## 四、回测方法设计

### 回测机制

```
历史选品数据
     │
     ├── 取出第N周时能获取的EchoTik数据
     ├── 用模型预测该批选品的成功率
     ├── 对比实际出单结果（T+7实际出单）
     │
     ├── Accuracy = 预测正确的个数 ÷ 总预测个数
     ├── Precision = 预测成功且实际成功 ÷ 预测成功的总数
     ├── Recall = 预测成功且实际成功 ÷ 实际成功的总数
     │
     └── 每轮回测后调整权重α₁~α₅
          └───→ 权重进化 → 下一轮更准
```

### 回测样例（模拟数据）
假设我们已有5批历史选品的EchoTik数据：

| 选品批次 | 品类 | P(success) | 实际7天出单 | 预测等级 | 实际表现 | 吻合? |
|:---------|:-----|:----------:|:----------:|:--------:|:--------:|:----:|
| 周1-美妆蛋 | 美妆工具 | 82分 | 87单 | 高成功 | ✅ 成功 | ✅ |
| 周1-粉扑 | 美妆工具 | 71分 | 43单 | 较高成功 | ✅ 成功 | ✅ |
| 周2-卷发棒 | 美发工具 | 58分 | 12单 | 中等 | ❌ 低于预期 | ❌ |
| 周2-收纳盒 | 家居 | 44分 | 3单 | 低概率 | ❌ 挂蛋 | ✅ |
| 周3-眼影刷 | 美妆工具 | 76分 | 56单 | 较高成功 | ✅ 成功 | ✅ |
| 周3-美容仪 | 个护 | 33分 | 0单 | 极小概率 | ❌ 挂蛋 | ✅ |

```
回测第1轮结果：
Accuracy = 5/6 = 83.3%  ← 整体准确率
Precision = 4/4 = 100%  ← 预测成功的都确实成功了（无虚假）
Recall = 4/4 = 100%     ← 实际成功的都预测成功了（无遗漏）
```

### 回测后的权重调整（梯度下降思路）

```
如果第1轮回测发现：
- 维度1(市场热度)很准 → 权重不变或微调
- 维度2(竞争生态)偏大 → 遇到竞争数据好的产品反而失败 → 降低α₂
- 维度4(利润空间)偏低 → 利润高的产品实际表现好 → 提高α₄

调整公式：
α_new(i) = α_old(i) + η × (实际误差方向)

η = 学习率（建议0.02，即每轮最多调2%）
```

## 五、模型可操作化

### 日常使用流程
```
1️⃣ 番茄从EchoTik看到选品
         ↓
2️⃣ 填入5维度评分所需的数据
         ↓
3️⃣ 🫘豌豆模型自动计算 P(success) + 预计7天出单量
         ↓
4️⃣ 等级建议输出：
       🟢≥85分 → 直接全量上架
       🟡55-84分 → 小规模测试
       🔴<55分 → 跳过
         ↓
5️⃣ 上架后7天：
        实际出单数据回流入模型
        用于下一轮权重调整
```

### 数据采集要求（番茄需要提供的字段）

| 字段 | 数据来源 | 必填 |
|:-----|:---------|:----:|
| 品类 | EchoTik选品 | ✅ |
| 目标GPM | EchoTik品类页 | ✅ |
| GPM 7日涨幅 | EchoTik趋势 | ✅ |
| 同类产品数估算 | EchoTik搜索 | ✅ |
| 竞品均价 | EchoTik商品页 | ✅ |
| TOP10 GMV占比 | EchoTik榜单 | ✅ |
| 是否有视频爆款先例 | EchoTik视频 | ✅ |
| 目标拿货价 | 1688搜索 | ✅ |
| 目标售价 | 定价策略 ×5.5 | ✅ |

## 六、模型局限性说明

| 局限 | 影响 | 缓解策略 |
|:----|:----|:---------|
| 初始权重来自经验估计 | 前几轮准确率可能偏低 | 5轮回测后自动优化 |
| 未考虑地区差异 | 同一品类在TH/MY表现不同 | 增加国家维度得分修正 |
| 未考虑季节突变因素 | 突发需求难预测 | 手动标记异常事件，排除计算 |
| 视频内容质量难量化 | 好视频能冲破所有模型限制 | 内容维度权重动态调整 |
| 选品数据完整性依赖番茄输入 | 数据缺失时模型不准 | 缺失字段取默认值+预测置信度标记 |

## 七、模型部署建议

### 最小可行版本（本周可用）
```
1. 用飞书多维表格建一个「选品预测表」
   字段：品类/5维度分/P(success)/等级/预计出单量/实际出单量
   
2. 手动填数据（初期） → 自动计算（后续用公式）
```
