## 一、飞书多维表格 API 与自动化能力评估

### 1.1 版本现状

| 维度 | 当前状态 |
|------|----------|
| **API 版本** | v1（稳定）、v2（部分功能灰度中） |
| **REST API 端点** | `open.feishu.cn/open-apis/bitable/v1/` |
| **主要操作** | 表管理（创建/删除/重命名）、记录增删改查、字段管理、视图配置 |
| **权限模式** | tenant_access_token + 文档 token（app_token） |
| **速率限制** | 约 100 次/秒（企业版更高） |

### 1.2 核心操作能力

**数据操作（REST API）：**
- `POST /v1/apps/:app_token/tables/:table_id/records` — 新增记录
- `PATCH /v1/apps/:app_token/tables/:table_id/records/:record_id` — 更新单条记录
- `POST /v1/apps/:app_token/tables/:table_id/records/batch_update` — 批量更新（最多 500 条）
- `GET /v1/apps/:app_token/tables/:table_id/records?page_size=&page_token=` — 列表查询（支持筛选/排序）
- `DELETE .../records` — 删除记录
- `POST .../records/search` — 搜索记录（按字段条件过滤）

**字段操作：**
- 支持动态创建/修改/删除字段
- 字段类型：文本、数字、货币、日期、单选、多选、成员、公式、查找引用、附件 等 30+ 类型
- ⚠️ 注意：字段 ID 是内部标识，API 操作使用 `field_id` 而非字段名

### 1.3 自动化（内置触发器）

2025-2026 年飞书多维表格自动化能力大幅增强：

| 触发类型 | 说明 | 适用场景 |
|---------|------|---------|
| 🔄 **定时触发** | 按分钟/小时/天/周/月周期执行 | 每日数据同步，定时跑批 |
| ➕ **新增记录时** | 记录被添加时触发 | 新订单录入后自动处理 |
| ✏️ **修改记录时** | 指定字段变更时触发（可设条件值） | 订单状态变更后发送通知 |

### 2.2 具体指标定义

#### L1 战略指标（双周看板）

| 指标 | 算法 | 阈值建议 | 备注 |
|------|------|---------|------|
| **总 GMV** | 全店全渠道总销售额 | 环比波动 <±30% 正常 | 分国家看趋势 |
| **总订单数** | 各店下单数总和 | — | 结合客单价看 |
| **综合退款率** | 退款笔数/总订单数 | >10% 告警 | 需按店铺分解 |
| **渠道 ROI** | 广告 GMV / 广告花费 | <2.5 告警 | 5国分别看 |
| **总毛利率** | (GMV-成本)/GMV | <35% 告警 | 含平台佣金+运费 |
| **市场份额** | 竞品对比 | — | 定期调研 |

#### L2 运营指标（每日看板）

| 指标 | 算法 | 阈值建议 |
|------|------|---------|

| **客服响应时间** | 首次回复耗时 | >5分钟告警（各国 SLA 不同） |
| **客服解决率** | 已解决/总工单 | <70% 告警 |
| **直播转换率** | 直播下单/直播观看 | <2% 告警 |
| **商品动销率** | 有销售的SKU/总SKU | <30% 告警 |
| **退货原因分布** | 退货原因 TOP5 | — |

#### L3 实时指标（分钟/小时级告警）

| 指标 | 粒度 | 预警逻辑 |
|------|------|---------|
| **实时订单异常突变** | 5分钟 | 订单量突然降为0（系统故障）或突然暴增（异常刷单） |
| **退款率短时飙升** | 30分钟 | 退款率 > 5% + 较上时段>200% |
| **差评/低分集中爆发** | 分钟级 | 30分钟内差评>3条 |
| **广告消耗异常** | 小时级 | 广告费消耗>日均2倍但GMV未同步增长 |
| **库存低于安全值** | 实时 | 库存 < 日均销量×3天 |
| **店铺在线/离线** | 实时 | 任一店铺API无响应>15分钟告警 |

## 三、告警规则设计（免打扰式异常检测）

### 3.1 核心原则

1. **宁可漏报、不可误报** — 误报=警报疲劳→真警报被忽略
2. **分级别通知** — P0（立即电话）→ P1（群消息）→ P2（日报汇总）
3. **避免重复告警** — 同指标30分钟内不重复推送
4. **时间窗口聚合** — 不要每条异常都报，聚合后发一条摘要
5. **基线动态调整** — 周末/大促/淡季用不同基线

### 3.2 告警层级设计

```
P0 🔴 紧急（24小时×7 推送到手机）
  ├─ 任一店铺 API 连续 15 分钟无返回数据
  ├─ 短时间内退款率 > 15% 且涉及金额 > $500
  ├─ TikTok Shop 平台本身宕机/封店通知
  └─ 库存极低+高售价SKU断货风险

P1 🟡 重要（推送到飞书群 @运营团队）
  ├─ 某店铺 GMV 较昨日同期下降 > 40%
  ├─ 退款率较昨日 > 100%（保持独立样本量 >20笔）
  ├─ 广告消耗 > 预算 120%
  └─ 客服响应时间 > 10分钟（某国持续1小时）

P2 🔵 关注（记入日报/周报汇总）
  ├─ 某国整体转化率下降 > 15%
  ├─ 动销率下降 > 5%（连续3天）
  ├─ 差评数较昨日 > 50%（绝对值>5）
  └─ 某SKU点击率持续下降趋势
```

### 3.3 异常检测算法

#### A. 环比（同比）比较法（最常用）

```
异常分 = |当前值 - 同期值| / 同期值

阈值设计：
  - 小时级：超过历史均值 ±3σ 或跳跃 >50%
  - 日级：超过前7日滚动均值的 ±2σ
  - 周级：同比上周同天 ±1.5σ（考虑周期效应）
```

#### B. EWMA（指数加权移动平均）基线

```
S(t) = α × X(t) + (1-α) × S(t-1)

适用场景：GMV、订单量等有自然波动的指标
α值建议：日粒度 0.3，小时粒度 0.1（平滑更多）
告警触发：|X(t) - S(t-1)| > β × σ_ewma
         β=3（严格）、β=2.5（中等）、β=2（宽松）
```

#### C. IQR（四分位距）法 — 抗异常基线

```
IQR = Q3 - Q1
正常范围：Q1 - 1.5×IQR 到 Q3 + 1.5×IQR

适用：退款率、退货率等分布不规律的指标
优势：不受极端值影响，天然抗干扰
```

#### D. 复合策略（推荐）

```
评分 = w1 × 环比偏离 + w2 × EWMA偏离 + w3 × IQR偏离
w1=0.3, w2=0.4, w3=0.3   ← 权重可配置

阈值 = 0.7（轻度告警）/ 1.0（中）/ 1.5（严重）

优势：三种方法互补，有效避免单方法误判
```

### 3.4 免打扰配置清单

| 策略 | 实现方式 |
|------|---------|
| **静默时段** | 23:00~08:00 仅推送 P0 告警 |
| **假期模式** | 大促期间扩大基线 1.5 倍避免误报 |
| **分层降噪** | 同指标30分钟内的多次告警合并为1条 |
| **持续异常升级** | 首报P2→持续2天升级P1→持续5天升级P0 |
| **季节性基线** | 按周几+是否月末+是否大促分别计算基线 |
| **国家差异化** | 各国有独立基线和阈值（刚开通的店铺用宽松阈值） |

### 3.5 告警疲劳阻止机制

```
Real Alert Rate = True Positive / (True Positive + False Positive)

目标：Real Alert Rate > 80%
监测：每周回顾告警精确率，动态调整阈值

如果某告警规则连续7天 >50% 误报 → 自动提升阈值 10%
如果某告警规则连续7天零触发 → 自动降低阈值 10%（或在预警报告中标注）
```

## 五、GEP 进化节点建议

以下是为 GEP（Generalized Evolutionary Planning）系统准备的进化建议，可作为下一步学习和系统优化的切入点：

### 🧬 节点 1：飞书多维表格分表策略优化
- **当前问题**：25店×5国数据量增长后，一张表性能下降
- **建议**：按国家分区表（印尼/泰国/...）+ 汇总视图（用飞书「查找引用」字段跨表汇总）
- **GEP 学习方向**：飞书多维表格的「数据容量限制」和「性能阈值」（建议实验 >10万条记录时的分表策略）
- **预计收益**：查询速度提升 3-5 倍

### 🧬 节点 2：自动化 Webhook 限流应对
- **当前问题**：25店同时推送 webhook 可能触发 50次/秒 上限
- **建议**：在中间层（n8n/Python）实现队列缓冲 + 批量写入飞书 API
- **GEP 学习方向**：研究飞书 API 批量接口（batch_update 上限 500条/次）与速率限制算法（令牌桶/漏桶）
- **预计收益**：避免数据丢失 + 降低 API 调用费用

### 🧬 节点 3：复合异常检测引擎
- **当前问题**：单一环比/EWMA 方法误报率较高
- **建议**：实现 3 种算法加权投票 + 自适应阈值调优（基于过去 7 天准确率自动调参）
- **GEP 学习方向**：学习 Prophet / 时序分解（STL）等进阶时序异常检测方法
- **预计收益**：精确率 >80%，误报率 <20%

### 🧬 节点 4：国家差异化基线系统
- **当前问题**：各国市场差异大，统一阈值不适合
- **建议**：为每个国家独立维护基线 + 动态适应进入期/成长期/成熟期不同阶段
- **GEP 学习方向**：按生命周期的阈值动态调整逻辑 + 店铺「冷启动」期用更宽松的基线算法
- **预计收益**：新开店前 2 周避免大量误报，成熟期精确度提升

### 🧬 节点 5：告警降噪自愈机制
- **当前问题**：运营人员手动关闭告警后，同类告警可能重复触发
- **建议**：引入告警状态机：触发→通知→确认→关闭→（如再触发，升级通知层级）→自动降噪学习
- **GEP 学习方向**：研究告警收敛算法（Alert Fatigue Reduction）、基于用户反馈的自动调参
- **预计收益**：运营告警处理效率提升 60%
